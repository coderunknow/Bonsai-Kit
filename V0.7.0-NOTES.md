# v0.7.0 audit notes

Phase 0 audit of the code this release builds on. Written before the durable pieces
(`serve.py`, the webui) were rewritten. Anything that contradicts the brief is flagged
under **Discrepancies** at the bottom — read that section before changing the contract.

## 1. The wire: what `/api/chat` proxies

`BonsaiClient.stream_chat(messages, **params)` returns a `ChatStream` (context manager,
`.close()` idempotent). Iterating it yields dicts; the local server re-emits each as one
SSE frame: `event: <type>\ndata: <json>\n\n`, flushed per frame.

| frame `event:` | data JSON | notes |
|---|---|---|
| `delta` | `{"kind":"delta","text":"…"}` | one content fragment; `text` is a str |
| `reasoning` | `{"kind":"reasoning","text":"…"}` | reasoning deltas are **separate** from content, never merged |
| `tool_call` | `{"kind":"tool_call","index":N,"call":{…}}` | passed through untouched; tool UI is v0.7.1 |
| `usage` | `{"kind":"usage","usage":{"prompt_tokens":N,"completion_tokens":N,"total_tokens":N}}` | emitted by the proxy from the terminal event, **before** `done` |
| `error` | `{"kind":"<error-class>","error":"…", …extras}` | for error frames only, `kind` is the *error class*, not the frame type (see §3) |
| `done` | `{"kind":"done","message":{…},"finish_reason":…,"usage":…,"timings":…,"elapsed":…,"ttft":…,"chunks":N,"model":…,"stopped":bool,"stream_id":…}` | terminal. `message` is the assistant message assembled so far — after a stop it contains the partial text and `stopped=true` |

Ordering on the happy path (asserted by tests): `delta`+ … → `usage` → `done`.
Usage comes from the server's final SSE payload (`stream_options.include_usage`); the
proxy never invents token counts. A `StreamInterrupted` retains `partial_text`,
`partial_reasoning` and the chunk count, so a mid-stream failure reports how much
arrived instead of pretending the turn completed.

## 2. Capability map

`CapabilityMap` states are exactly **`supported` / `unsupported` / `unknown`** — three
values, nothing else, and `unknown` is first-class (never rendered as "no").
`to_dict()` → `{fields: {name: state}, evidence: {name: text}, facts: {free-form}}`.
Known fields: `reasoning_effort, thinking_budget_tokens, tools, tool_choice,
response_format, min_p, top_k, stream_options`. Facts are learned lazily:
`context_window` and `vision`/`vision_source` come from `/props` (`probe_vision()` reads
`modalities.vision` when the build announces it), `served_models` from `/v1/models`.
`/api/capabilities` calls `props()` + `probe_vision()` first so facts are populated,
then returns `to_dict()` **verbatim**.

Doctor's separate check vocabulary: `PASS / FAIL / SKIP / UNKNOWN / DEGRADED`.

## 3. The error classes

The brief says "four error classes" but lists five failure states. All five get a
distinct `kind`, plus two extra kinds the concurrency/malformed-body requirements force:

| `kind` | raised as | UI treatment |
|---|---|---|
| `connection` | `TransportError` (refused/DNS/timeout during connect), or no endpoint configured | "deployment probably down — rerun the cell" |
| `unauthorized` | `BonsaiAPIError` status 401/403 | points at the key field; the cell prints the key exactly once |
| `remote` | `BonsaiAPIError` other statuses (5xx, 429…) | includes `status` + `hint()` from `errors.py` |
| `mid_stream` | `StreamInterrupted` — died after N chunks | retry offered, `tokens_arrived` reported |
| `stall` | no bytes for T seconds (proxy watchdog, default 30 s, `BONSAI_SERVE_STALL` override) | says how long it waited |
| `busy` | stream registry at capacity, or duplicate active `stream_id` | refuse clearly, never queue silently |
| `bad_request` | malformed/invalid request body | 400 |

Pre-stream failures answer with an HTTP status + JSON `{"error":…, "kind":…}`; failures
after streaming started are SSE `event: error` frames with `kind` = the class above.

## 4. Stop contract

There is no `StreamHandle` here (see Discrepancies): `ChatStream.close()` is the stop.
It is idempotent, closes the HTTP response deterministically, and marks the transport
released — the same seam `test_streaming_recovery` already asserts
(`transport._stream_outstanding is False` after cancellation). The proxy's stop does:
mark entry stopped → `close()` → the reader thread observes the abort → writer emits a
terminal `done` with `stopped=true` and the partial `message` retained. `/api/stop` is
idempotent (`{ok:true, found:bool}` for unknown ids). A client disconnect (closed tab)
runs the same close path, so the remote serving slot is never left busy.

## 5. Why a second web UI is justified

The PrismML runtime ships a chat UI at the tunnel root, but that UI dies with the
runtime and its URL, speaks directly to an endpoint anyone holding the tunnel URL can
reach, and cannot see the local machine's config/session files or the CLI's provenance
("user set" vs "default"). The local UI keeps the bearer key inside the Python process
(browser never sees it — same-origin proxy, no CORS), works from the same layered config
the CLI uses, and drives every control from the same capability map the doctor prints,
so settings behave identically whether you are in a terminal or a tab. It is the stable
entrypoint across ephemeral deployments: the tunnel changes every rerun, `--serve`
does not.

## 6. Where the existing code fights this slice

1. **`ChatStream` owns socket cleanup.** The proxy must never read the HTTP response
   itself or close it out from under the stream — all cancellation flows through
   `ChatStream.close()`, and the stall watchdog needs a reader thread + queue because
   `read1()` blocks inside the stream's own iterator.
2. **Capability facts are learned lazily.** `/api/capabilities` before any call has
   happened returns mostly `unknown`; the route must populate facts (props/vision)
   first, and the UI must render `unknown` as "unknown", never as "no".
3. **Config precedence is layered** (defaults → file → env → flags, `explicit_args`
   marks what the user actually typed). `/api/config` must round-trip through
   `config.py`'s file and keep provenance intact instead of flattening everything into
   "value".

## Discrepancies between the brief and this repo (flagged, not silently redesigned)

- The brief names `stream_assistant_reply` → `StreamHandle.stop()` and
  `BonsaiClient.chat_stream`. Neither exists in this checkout: the transport is
  `BonsaiClient.stream_chat()` → `ChatStream.close()`. Behaviour matches the contract
  the brief wants (stop mid-flight, partial retained, connection released, covered by
  `test_streaming_recovery`); only the names differ, so the proxy uses the real names.
- The brief says "four error classes" but enumerates five failure states; implemented
  as five + `busy` + `bad_request` (§3).
- The brief says start from tag `v0.6.0` (`10f3bbb`). No such tag or commit exists in
  this clone (`git tag -l` is empty; `10f3bbb` is not a valid object). `main` is at
  `5cb9b50`, which already contains a partial v0.7.0 skeleton from a previous session
  (a 71-line `serve.py` and a 2 KB vanilla-JS `dist/`). This session continues from
  `5cb9b50` and replaces that skeleton with the real thing; no history was rewritten.
- The brief's static route table lists only `GET /` and `/ui/<path>`. Vite with
  `base: './'` makes `index.html` at `/` reference `./assets/…` → `/assets/…`, so the
  server additionally serves other non-`/api` paths out of `dist/` (still
  traversal-safe, 404 on miss, no listing). Noted as a deliberate superset.
- The brief's test plan mentions "the harness's invocation log" for the disconnect
  assertion. `mock_bonsai_server` logs requests (`get_paths`, `calls`) but closing the
  client's response generates no new mock request, so the disconnect test asserts via
  the same seam the existing cancellation tests use: `transport._stream_outstanding`
  flips to `False` and the stream registry drains.

## Additions found while building (kept honest, not silently redesigned)

- **`bonsai_notes`** appear on non-stream `chat()` responses (`data['bonsai_notes'] =
  [...]`, client.py) when a field had to be dropped. In the streaming path the same
  drops surface as `caps.note_400(...)` evidence instead, so the web UI learns them
  through `/api/capabilities.evidence`, not through the frame stream.
- **One client per stream.** `HttpTransport` owns exactly one connection and one
  `_stream_outstanding` flag; sharing one client across concurrent streams (or with
  the GET routes) lets one teardown close another's socket. `serve.py` therefore gives
  each `POST /api/chat` a private `BonsaiClient` and shares only the `CapabilityMap`
  (so a stream's `note_400` still teaches the settings panel). The GET routes use a
  long-lived template client. Concurrency cap stays 4, refused with `kind: busy`.
- **Stop must not block on the stream's own reader.** `HTTPResponse.close()` waits for
  the buffer lock that the reader thread holds inside `recv()` — on a silent upstream
  that wait would last until the read timeout (observed: a stall error delayed by the
  mock's 5-second sleep). `_StreamEntry.close()` shuts the raw socket down first
  (`SHUT_RDWR`), which makes `recv()` return immediately; the (now dead) socket is
  then explicitly dropped from the transport pool instead of being re-pooled.
- **`GET /api/capabilities` probes the two reasoning controls** (`probe_field`) the
  way the doctor does, because nothing else ever fills those states — without it the
  settings panel could only ever show `unknown`. Probes are cached in the shared map;
  when the state is already known no probe request is made.
- **Measured prompt tokens** (brief §6) come from `usage.prompt_tokens` of the last
  completed turn, displayed against the `/props` context window. No new
  `/api/tokenize` route was added — the brief's route table does not include one, and
  usage numbers are the server's own measurements of the turn just finished.
- **Stopped-turn token count.** Usage normally never arrives on a stopped stream (the
  server aborts before its final payload), so `/api/chat` reports `done.tokens` as:
  `usage.completion_tokens` if usage was seen, else the endpoint's own
  `/tokenize` count of the partial text, else `null`. A number is only ever shown
  when it was measured.
